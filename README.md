## Recent work

**[shop-support-agent](https://github.com/Exalt24/shop-support-agent)** answers customers for a Shopify store from the store's own orders and policy file and hands anything it should not decide to a person: a legal threat, a chargeback or a request for a human is matched in code before the model sees the message, and a guard refuses any reply with a figure or a promise the facts do not back. Enquiries are routed to an owner queue, and with the visitor's explicit yes they become a Zoho CRM lead, a follow-up task and a note, written from Zoho's v8 documentation and tested against a stand-in server. An embeddable chat widget serves two demo websites, each with its own theme and owner queue, and a Zoho MCP server lets an agent look up a lead or add a note only with a confirm flag and an idempotency key. 483 tests, including a real browser on both sites, and 131 deliberate breaks that each fail a test; the Shopify side ran against a development store and the Zoho side against a stand-in server written from Zoho's own documentation.

**[sipclerk](https://github.com/Exalt24/sipclerk)** answers an inbound SIP call for a law firm with its own small SIP and RTP stack, a Pipecat voice pipeline and the intake rules in a state machine and a guard instead of a prompt, so a caller who asks for legal advice is told once that it cannot give any and a caller who needs a person is handed to one as a second SIP call. Each firm's records are encrypted under its own key with an audit line for every read, and a finished intake goes out as a signed, retried delivery. Three independent review passes found the bugs I liked least, such as office hours read from a fixed offset after the clocks changed and a transfer leg that outlived its call, and each class is pinned by a generated test. About 4,000 tests and about 250 deliberate breaks of the code that each fail a test; it runs end to end on localhost with test voices and sample firms.

**[clinic-call-console](https://github.com/Exalt24/clinic-call-console)** is a review console for the calls a clinic's voice assistant takes: details are masked when a call arrives, an admin reveals one only with a reason, and the reveal is audited in the same transaction. The Angular app runs against either a Spring Boot or a NestJS and PostgreSQL API with the same contract, and the NestJS side has a contract test against the Angular client's types and a script that removes 41 guards one at a time, each caught by a test.

**[enterprise-rag-knowledge-base](https://github.com/Exalt24/enterprise-rag-knowledge-base)** is a FastAPI RAG service on Qdrant, with vector search, BM25 hybrid and optional reranking. The bug I'm happiest I found: ranking was putting the best results last. After the fix I built a rerunnable evaluation around it, with hit-at-k and MRR on a generated corpus, a pinned baseline and a mutation check that run in CI, so the next ranking bug fails a test. It also has a read-only MCP server and an agent skill, so Claude Code can search the knowledge base and cite the chunk each answer came from. I also took torch out of the deployed image so it fits a 512 MB instance. It also has a Google Cloud Vertex AI Gemini provider, tested against a stand-in server written from Google's documentation.

**[api-analytics-hub](https://github.com/Exalt24/api-analytics-hub)** pulls a live Shopify store into Postgres with row-level security per tenant. Its isolation test caught a cross-tenant leak that came from a superuser connection, and a pgvector search under row-level security returned 1.87 of 20 rows until the iterative scan was turned on. A price-watch module reads competitor pages in Chromium, holds an uncertain match for a person and syncs only approved price changes to Shopify and Zoho Inventory. A prepaid wallet and billing ledger keeps a double-entry record in cents and writes each money command and each provider webhook event once, tested against a stand-in Stripe server written from its documentation. An LLM copywriter won't publish a number that is not in the source facts, a Slack alert flags syncs that are stuck or stale, and a backup script restores each dump into a throwaway database before it counts (the first real restore found a migration bug). A Caddyfile and systemd timers schedule that backup, and I ran the shipped units under a real systemd in a container. 5,224 tests and 289 mutation guards. The repo's README holds the rest.

**[multi-agent-research](https://github.com/Exalt24/multi-agent-research)**: seven LangGraph agents split a market research question between them. The fact checker can pause the run, so a person decides whether to continue. One agent asked Groq's free tier for roughly 11,000 tokens a minute against an 8,000 ceiling and could never finish; its budgets are now named constants that sit under that ceiling.

**[clio-matter-bridge](https://github.com/Exalt24/clio-matter-bridge)** connects to Clio with live OAuth. The webhook receiver is checked against real signed deliveries, and nothing that identifies a client gets sent to a language model. 265 assertions, and every test run deletes three guards to check the suite goes red.

**[ghl-tenant-bridge](https://github.com/Exalt24/ghl-tenant-bridge)**: GoHighLevel into Supabase, a Cloudflare Worker receiver on D1 that forwards through a Cloudflare Queues consumer with a dead letter queue as well as on a cron, under a mutation-checked test suite. A Python relay fans leads out to Slack, Make, Meta Conversions API and Google Sheets and pulls ad spend, all built against stand-in servers written from the vendors' documentation. Terraform for ECS Fargate and RDS Postgres is tested offline with a mocked provider and a 49-mutant harness, and a Hasura GraphQL layer sits over the PostGIS tables. Radius matching uses the PostGIS distance, because a bounding box would have matched a property 67.2 km from a 50 km storm. A farm-list intake rejects a bow-tie polygon instead of repairing it into two plots (61 checks, 17 mutants), and an offline capture queue serves field crews.

**[camlobe](https://github.com/Exalt24/camlobe)** is a Django and PostgreSQL pipeline that turns auto parts supplier feeds into one catalog: files, SFTP, paged REST, SOAP and an HTTP scraper behind one interface, raw rows kept as received, the same part matched across suppliers without fuzzing, X12 order documents, and search through REST and Meilisearch. A feed cut inside its last row, or a walk whose total moves, ends as a partial run instead of delisting a live part. 1,025 tests and 323 guards that a mutation check breaks one at a time, all caught; built against local test servers.

**[agent-harness-lab](https://github.com/Exalt24/agent-harness-lab)** is a small TypeScript agent harness for local models: loop guards, a context that keeps the full tool result retrievable, and an eval runner that scores a model with confidence intervals. On a 4B model it showed that setting the temperature mattered for tool choice, and that temperature 0 made one case a certain miss. A mutation check removes each guard in turn and a test has to fail.
