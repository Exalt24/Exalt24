## Recent work

**[parcelkey](https://github.com/Exalt24/parcelkey)** links messy Australian property addresses to one stable property id on PostgreSQL and PostGIS, and keeps the rule and score behind every link. What it cannot decide is set aside with a reason code, and a different unit never matches. A seeded answer key scores precision, recall and the recall that counts what it sets aside, measured on a generated address set.

**[sheetdesk](https://github.com/Exalt24/sheetdesk)** is a set of Google Apps Script tools on Google Workspace for a small marketing agency, deployed with clasp: a custom menu and sidebar, monthly client summary tabs, an emailed report PDF and a web app that takes leads. It ran on a real Google account with sample agency data, and a review round found a wrong Gmail scope and month text that Sheets read as a date, each fixed after a test reproduced it. The tests run against a local fake of Google's services, and a Data Studio (Looker Studio) report on the same Sheet shows spend over time: [the report](https://datastudio.google.com/reporting/e3ad4a80-d1d2-47cb-bdfd-20df33d35874).

**[xerlane](https://github.com/Exalt24/xerlane)** loads Primavera XER schedules, cost and commitment exports and Autodesk model data into PostgreSQL, one set of tables per client under forced row level security. A reconcile step proves the data equals the file, and it was shown to catch one cent of damage. It reports earned value by task, cost code and model element, and a Nuxt app shows each client only its own projects. It ran on generated schedules, and the Autodesk connector was tested against a stand-in server written from Autodesk's documentation.

**[shop-support-agent](https://github.com/Exalt24/shop-support-agent)** answers customers for a Shopify store from the store's own orders and policy file, and anything it should not decide goes to a person. A legal threat, a chargeback or a request for a human is matched in code before the model sees the message, and a guard refuses any reply with a figure or a promise the facts do not back. With the visitor's yes, an enquiry becomes a Zoho CRM lead, tested against a stand-in server written from Zoho's documentation. The Shopify side ran against a development store.

**[enterprise-rag-knowledge-base](https://github.com/Exalt24/enterprise-rag-knowledge-base)** is a FastAPI RAG service on Qdrant with vector search, BM25 hybrid and optional reranking. Ranking was putting the best results last, and after the fix I built a rerunnable evaluation (hit-at-k and MRR, a pinned baseline and a mutation check) that runs in CI, so the next ranking bug fails a test. Claude Code can search it through a read-only MCP server and cite the chunk each answer came from, and I took torch out of the deployed image so it fits a 512 MB instance. The evaluation corpus is generated, so its intervals are wide.

**[api-analytics-hub](https://github.com/Exalt24/api-analytics-hub)** pulls a live Shopify store into Postgres with row-level security per tenant, and its isolation test caught a cross-tenant leak. A pgvector search under row-level security returned 1.87 of 20 rows until the iterative scan was turned on. A Reports page in its Next.js dashboard exports a month as CSV, Excel or PDF and checks an AI summary against the data with a code guard. The ad and business connectors, such as Google Ads and QuickBooks Online, were tested only against stand-in servers, and its README holds the rest.

**[multi-agent-research](https://github.com/Exalt24/multi-agent-research)** has seven LangGraph agents that split a market research question between them. The fact checker can pause the run, so a person decides whether to continue. One agent asked Groq's free tier for roughly 11,000 tokens a minute against an 8,000 ceiling and could never finish. Its budgets are now named constants that sit under that ceiling.

**[clio-matter-bridge](https://github.com/Exalt24/clio-matter-bridge)** connects to Clio with live OAuth. The webhook receiver is checked against real signed deliveries. Nothing that identifies a client gets sent to a language model. There are 265 assertions, and every test run deletes three guards to check the suite goes red.

**[ghl-tenant-bridge](https://github.com/Exalt24/ghl-tenant-bridge)** moves GoHighLevel data into Supabase through a Cloudflare Worker receiver on D1 with a Queues consumer and a dead letter queue, and a Python relay that sends leads to Slack, Make, Meta Conversions API and Google Sheets. Radius matching uses the PostGIS distance, since a bounding box matched a property 67.2 km from a 50 km storm. In a free HighLevel developer account it also holds a published funnel, custom fields and a calendar booking made through the API. The Worker and the relay were built against stand-in servers written from the vendors' documentation.

**[camlobe](https://github.com/Exalt24/camlobe)** is a Django and PostgreSQL pipeline that turns auto parts supplier feeds into one catalog. Files, SFTP, paged REST, SOAP and an HTTP scraper sit behind one interface, and the same part is matched across suppliers without fuzzing. A feed cut inside its last row ends as a partial run instead of delisting a live part. It was built and tested against local test servers and sample supplier feeds.

**[agent-harness-lab](https://github.com/Exalt24/agent-harness-lab)** is a small TypeScript agent harness for local models. It has loop guards, a context that keeps the full tool result retrievable, and an eval runner that scores a model with confidence intervals. On a 4B model it showed that setting the temperature mattered for tool choice, and that temperature 0 made one case a certain miss. A mutation check removes each guard in turn and a test has to fail.
