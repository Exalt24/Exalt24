## Recent work

**[xerlane](https://github.com/Exalt24/xerlane)** loads Primavera XER schedules, cost and commitment exports and Autodesk model data into PostgreSQL, one set of tables per client. Row level security is forced on every client table. Rows that fail validation are set aside with their line numbers. A reconcile step proves the data equals the file, and it was shown to catch one cent of damage. It reports earned value by task, cost code and model element. A Nuxt and TypeScript app lets a client's staff sign in and see only their own projects. The Autodesk connector was written from Autodesk's documentation and tested against a stand-in server that follows it. There are 953 tests, and 1,757 of 1,757 mutants were caught when each guard was broken on purpose. A dependency-free Rust tokenizer for the XER file structure matched the Python parser on 461 files with no differences. It is a tokenizer, not a loader.

**[shop-support-agent](https://github.com/Exalt24/shop-support-agent)** answers customers for a Shopify store from the store's own orders and policy file. Anything it should not decide goes to a person. A legal threat, a chargeback or a request for a human is matched in code before the model sees the message. A guard refuses any reply with a figure or a promise the facts do not back. Enquiries go to an owner queue, and with the visitor's explicit yes they become a Zoho CRM lead, a follow-up task and a note, written from Zoho's v8 documentation and tested against a stand-in server. An embeddable chat widget serves two demo websites, each with its own theme and owner queue. A Zoho MCP server lets an agent look up a lead or add a note only with a confirm flag and an idempotency key. It can also answer through the Claude API or IBM watsonx.ai, each written from the vendor's documentation and tested against a stand-in server that follows it. There are 836 tests, including a real browser on both sites, and 325 deliberate breaks that each fail a test. The Shopify side ran against a development store, and the Zoho side against a stand-in server written from Zoho's own documentation.

**[sipclerk](https://github.com/Exalt24/sipclerk)** answers an inbound SIP call for a law firm. It has its own small SIP and RTP stack and a Pipecat voice pipeline. The intake rules live in a state machine and a guard, not in a prompt. A caller who asks for legal advice is told once that it cannot give any. A caller who needs a person is handed to one as a second SIP call. Each firm's records are encrypted under its own key, with an audit line for every read. A finished intake goes out as a signed, retried delivery. Three independent review passes found the bugs I liked least, such as office hours read from a fixed offset after the clocks changed and a transfer leg that outlived its call. Each class is pinned by a generated test. There are about 4,000 tests and about 250 deliberate breaks of the code that each fail a test. It runs end to end on localhost with test voices and sample firms.

**[clinic-call-console](https://github.com/Exalt24/clinic-call-console)** is a review console for the calls a clinic's voice assistant takes. Details are masked when a call arrives. An admin reveals one only with a reason, and the reveal is audited in the same transaction. The Angular app runs against either a Spring Boot or a NestJS and PostgreSQL API with the same contract. The NestJS side has a contract test against the Angular client's types, and a script that removes 41 guards one at a time, each caught by a test.

**[enterprise-rag-knowledge-base](https://github.com/Exalt24/enterprise-rag-knowledge-base)** is a FastAPI RAG service on Qdrant, with vector search, BM25 hybrid and optional reranking. Early on, ranking was putting the best results last. After the fix I built a rerunnable evaluation around it: hit-at-k and MRR on a generated corpus, a pinned baseline and a mutation check, all run in CI, so the next ranking bug fails a test. It also has a read-only MCP server and an agent skill. Claude Code can search the knowledge base and cite the chunk each answer came from, and Hermes Agent ran the same server and skill. I took torch out of the deployed image so it fits a 512 MB instance. It has a Google Cloud Vertex AI Gemini provider, tested against a stand-in server written from Google's documentation. Excel workbooks upload too, and an answer cites the sheet and cell range.

**[api-analytics-hub](https://github.com/Exalt24/api-analytics-hub)** pulls a live Shopify store into Postgres with row-level security per tenant. Its isolation test caught a cross-tenant leak. A pgvector search under row-level security returned 1.87 of 20 rows until the iterative scan was turned on. A Reports page in its Next.js dashboard exports a tenant's month as CSV, Excel or PDF through Server Actions, reads through Kysely under forced row-level security, and checks an AI summary against the data with a code guard. It is tested against a scripted fake model, a stand-in Anthropic server and SeaweedFS as the S3 stand-in. A price-watch module reads competitor pages in Chromium, holds an uncertain match for a person. A prepaid wallet and billing ledger writes each money command and webhook event once, through the official Stripe SDK. An LLM copywriter won't publish a number that is not in the source facts. A backup script restores each dump into a throwaway database before it counts. A DigitalOcean Terraform setup (applied once, then destroyed), a Twilio SMS sender and a Nix flake dev shell sit beside it. Google Ads, TikTok Ads, Square, QuickBooks Online, Shopmonkey and Google Business Profile connectors feed a cost per conversion report, tested only against stand-in servers. 6,612 tests plus 129 dashboard tests, 10 browser tests and 65 deliberate breakages each caught; its README holds the rest.

**[multi-agent-research](https://github.com/Exalt24/multi-agent-research)** has seven LangGraph agents that split a market research question between them. The fact checker can pause the run, so a person decides whether to continue. One agent asked Groq's free tier for roughly 11,000 tokens a minute against an 8,000 ceiling and could never finish. Its budgets are now named constants that sit under that ceiling.

**[clio-matter-bridge](https://github.com/Exalt24/clio-matter-bridge)** connects to Clio with live OAuth. The webhook receiver is checked against real signed deliveries. Nothing that identifies a client gets sent to a language model. There are 265 assertions, and every test run deletes three guards to check the suite goes red.

**[ghl-tenant-bridge](https://github.com/Exalt24/ghl-tenant-bridge)** moves GoHighLevel data into Supabase. A Cloudflare Worker receiver on D1 forwards through a Cloudflare Queues consumer with a dead letter queue, as well as on a cron, under a mutation-checked test suite. A Python relay fans leads out to Slack, Make, Meta Conversions API and Google Sheets and pulls ad spend. All of it was built against stand-in servers written from the vendors' documentation. Terraform for ECS Fargate and RDS Postgres is tested offline with a mocked provider and a 49-mutant harness. A Hasura GraphQL layer sits over the PostGIS tables. Radius matching uses the PostGIS distance, because a bounding box would have matched a property 67.2 km from a 50 km storm. A farm-list intake rejects a bow-tie polygon instead of repairing it into two plots (61 checks, 17 mutants). An offline capture queue serves field crews.

**[camlobe](https://github.com/Exalt24/camlobe)** is a Django and PostgreSQL pipeline that turns auto parts supplier feeds into one catalog. Files, SFTP, paged REST, SOAP and an HTTP scraper sit behind one interface. Raw rows are kept as received. The same part is matched across suppliers without fuzzing. It handles X12 order documents, and search runs through REST and Meilisearch. A feed cut inside its last row, or a walk whose total moves, ends as a partial run instead of delisting a live part. There are 1,025 tests and 323 guards that a mutation check breaks one at a time, all caught. It was built against local test servers.

**[agent-harness-lab](https://github.com/Exalt24/agent-harness-lab)** is a small TypeScript agent harness for local models. It has loop guards, a context that keeps the full tool result retrievable, and an eval runner that scores a model with confidence intervals. On a 4B model it showed that setting the temperature mattered for tool choice, and that temperature 0 made one case a certain miss. A mutation check removes each guard in turn and a test has to fail.

**[ledgerbell](https://github.com/Exalt24/ledgerbell)** runs scheduled paper trading routines on Alpaca with alerts, a dashboard and risk rules the code cannot skip. One order gateway applies a maximum position size, a daily loss limit, a stop on every entry that lives at the broker and a kill switch. A Claude Code step runs with every tool off, so it can suggest orders and never place one. In a made-up trading day the market dropped 40 percent overnight, the loss limit tripped the kill switch and the next open was refused. It also has an options leg that can only buy one long call or put to open, a Finnhub price option and an Airtable run log. It has 208 tests and ran on a real Alpaca paper account in market hours, where the runs found bugs the test server had hidden.
